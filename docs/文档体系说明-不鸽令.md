# 文档体系说明 - 不鸽令

## 1. 当前产品定位

`不鸽令` 已不再只是“线下契约引擎”。

当前项目的正确理解方式是两层结构：

- 表层产品：同城低成本组局平台
- 底层能力：线下契约引擎

也就是，用户看到的是“模板化发局、附近分发、报名支付、签到评价、战报复用”的组局产品；平台底层仍然依赖押金履约、信用体系、核销/签到、仲裁和分账来保证线下履约质量。

## 4. 事实优先级

当多份文档出现描述差异时，按下面顺序判断哪份是当前事实来源：

1. 代码与测试
2. `README.md`
3. `UGC 同城低成本组局小程序.md`
4. `实施计划-不鸽令UGC组局化改造.md`
5. `API接口文档-不鸽令.md`
6. 底层引擎基线文档

换句话说，旧的“线下契约引擎”文档可以解释为什么这个系统最初这么设计，但不能覆盖当前组局平台的定位。

---

## 5. 维护规则

- 新增表层组局能力时，优先更新 `README.md`、API 文档、部署文档。
- 影响产品定位、用户路径、增长闭环时，优先更新 `UGC 同城低成本组局小程序.md` 和实施计划。
- 只影响底层履约/支付/仲裁机制时，再回头补充旧引擎基线文档。
- 如果某份旧文档内容仍然有效，但定位已经不是“当前主定义”，应明确标注“底层基线”或“历史基础”，不要假装它还是最新产品说明。

这份文档的目的只有一个，避免读者再把“底层线下契约引擎”误当成“当前整个平台”。
